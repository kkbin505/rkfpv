# rkfpv 技术路线：Luckfox 原厂 SDK + 自写推流 + wfb-ng

> 硬件：Luckfox Pico Mini（RV1103，TF 卡版）+ SC3336 + RTL8812AU
> 目标：不用 OpenIPC 的 majestic，完全掌控“采集 → 编码 → 无线”这条链路
> 代码：`~/github/rkfpv/`（github.com/kkbin505/rkfpv）　SDK：`~/github/luckfox-pico/`

---

## 1. 为什么换掉 majestic

- **起因**：横向平移时画面错位/撕裂，三个地面站（PixelPilot、Linux、CoreELEC）表现一样，说明问题出在天空端。
- **majestic 是什么**：OpenIPC 的推流程序，**闭源**，只发布各芯片平台的二进制。它把各家厂商 SDK 包了一层，用统一的 `majestic.yaml` 配置：
  - 采集 / ISP：sensor 初始化、曝光、白平衡、日夜切换
  - 编码：H.264/H.265、码率、GOP、帧率
  - 输出：RTSP、ONVIF、网页、抓图、录像；FPV 模式下写 `rtp_local` unix socket 给 `wfb_tx`
  - 附加：OSD、音频、移动侦测、HTTP API（alink 就是靠它调码率）
- **问题**：编码器内部参数（wrap、slice、码率峰值等）只能改它开放的那些；出了问题也读不到源码排查。
- **结论**：只用一家芯片（瑞芯微）的话，直接调用厂商 SDK 就行，majestic 这层可以去掉。代价是程序跟芯片绑定，RTSP/网页/OSD 也没了（FPV 用不上）。

### OpenIPC 原配置为什么吃不消（顺带记录）

- `video_settings` 首次启动写入：8000 kbps、CBR、60fps、H.265。
- `wfb.yaml`：MCS 2、20 MHz、FEC 8/12、无 STBC/LDPC，实际可用带宽约 6 Mbps，**8 Mbps 超出了链路能力**。
- 现场可调的命令：
  - `wifibroadcast cli -s .broadcast.mcs_index N`
  - `wfb_tx_cmd 8000 set_radio -B 20 -G long -S 0 -L 0 -M 3`
  - `cli -s .video0.bitrate N; killall -1 majestic`

## 2. 整体架构

```
SC3336 ─► rkaiq(ISP) ─► RKMPI VI ─► VENC H.265 ─► rkfpv(RTP 封包) ─► UDP 127.0.0.1:5600
                                                                          │
飞控 ◄─UART3─► mavbridge ◄─UDP 14550/14551─►                             ▼
                                              wfb_tx / wfb_rx ─► RTL8812AU（monitor 模式注入）
                                                                          │ 空中
                                                                          ▼
                                                        地面站（PixelPilot / Linux / CoreELEC，不用改）
```

**分工**：

| 层 | 原来（OpenIPC） | 现在 |
|---|---|---|
| 采集 + ISP + 编码 | majestic（闭源） | **rkfpv**（自写，调 RKMPI） |
| 编码参数 | `majestic.yaml` + `cli` | `/etc/rkfpv.conf` |
| 无线链路 | wfb-ng | wfb-ng（不变） |
| 链路参数 | `/etc/wfb.yaml` | `/etc/wfb.yaml`（格式不变） |
| MAVLink | wfb 自带串口转发 | **mavbridge**（UART3） |
| 运行时改码率 | majestic HTTP API | `killall -HUP rkfpv` |

地面端不用改任何东西：密钥、link_id、信道、无线端口号都和 OpenIPC 保持一致，RTP 照样落在 UDP 5600。

## 4. wfb-ng 为什么还要保留

wfb-ng 负责“数据怎么飞过去”，和 majestic 负责的“画面怎么来”是两回事，两者只靠 UDP 5600 交接。

普通 WiFi 做不到、wfb-ng 能做到的：

1. **不用连接，直接广播**：monitor 模式注入原始 802.11 包，没有关联过程，远了只会花屏，不会断开重连。
2. **没有 ACK、没有重传**：靠 FEC 补丢包。`fec 8/12` = 每 8 个数据包加 4 个冗余包，12 个里丢任意 4 个都能恢复。
3. **速率固定**：MCS 由自己定，不会被驱动的速率自适应乱调。
4. **加密 + 认证**：`drone.key` / `gs.key`。
5. **多路复用**：视频（端口 0）、MAVLink 下行（16）、上行（144）、tunnel（0x20/0xa0）共用一块网卡。
6. **地面分集**：地面站可以插多块网卡同时收。

## 5. 关键设计决定

- **固件**：Luckfox 原厂 SDK（Buildroot 2023.02.6），不用 OpenIPC。
- **板型**：TF 卡版（`BoardConfig-SD_CARD-Buildroot-RV1103_Luckfox_Pico_Mini-IPC.mk`），刷写方便。
- **起步参数**：1280×720 @ 30fps，H.265 CBR 3500 kbps，GOP 30。MCS 2（约 6 Mbps）下留足余量，稳定后再试 720p60、1080p30。
- **默认关闭 wrap**：先把相机端编码排除在撕裂原因之外。slice 拆分、intra refresh 可选。
- **无 OSD**。
- **MAVLink 走 UART3**：`/dev/ttyS3`，115200。引脚：TX = GPIO1_D0，RX = GPIO1_D1。
- **USB 角色自动切换**（只有一个 OTG 口）：
  - 插电脑（gadget 状态变成 `configured`）→ 保持 device 模式，ADB/RNDIS 可用，不启动 FPV（调试模式）
  - 其它情况（OTG 转接 RTL8812AU）→ 切 host 模式，启动 FPV
  - 强制开关：`/userdata/fpv.force` 总是启动 FPV，`/userdata/fpv.off` 总是不启动

## 6. 代码结构（`rkfpv/`）

| 文件 | 作用 |
|---|---|
| `src/main.c` | ISP → `RK_MPI_SYS_Init` → VI（NV12, DMABUF）→ VENC H.265 → `RK_MPI_SYS_Bind` → `GetStream` 循环；PTS µs→90 kHz；`bFrameEnd` 置 marker；SIGHUP 重读码率/GOP 并请求 IDR |
| `src/isp.c` | rk_aiq_uapi2 初始化，AE 固定帧率，镜像/翻转 |
| `src/rtp_h265.c` | RFC 7798 封包：小 NAL 单包发送，大 NAL 用 FU 分片；PT 96 |
| `src/config.c` | `/etc/rkfpv.conf`（key=value）+ 命令行 `-s key=value` |
| `src/mavbridge.c` | UART ↔ UDP，按 MAVLink v1/v2 帧聚合发送（参数 `-a 15 -m 1000 -t 30`） |
| `files/wfb.sh` | 精简自 OpenIPC `wifibroadcast`：加载驱动 → monitor 模式 → `wfb_tx -u 5600` + 遥测 |
| `files/S21appinit` | 替换 SDK 自带的：保留 oem 初始化和 camera 驱动加载，**不启动 rkipc** |
| `files/S99fpv` | USB 角色判断 → `wfb.sh start` → 启动 rkfpv |
| `files/rkfpv.conf` / `wfb.yaml` | 默认配置 |
| `luckfox/build-deps.sh` | 交叉编译 wfb-ng、88XXau.ko |
| `luckfox/mkoverlay.sh` | 拼装 SDK overlay `overlay-rkfpv` 并挂进板级配置 |
| `test/` | 封包单测、GStreamer 端到端解码（150 帧全部解出）、mavbridge pty 测试 |

## 7. SDK 改动（`luckfox-pico/`）

- **DTS** `rv1103g-luckfox-pico-mini.dts`：`usbdrd_dwc3` 的 `dr_mode` 改为 `"otg"`（原来是 peripheral）；`&uart3` 设为 `okay`。
- **内核** `luckfox_rv1106_linux_defconfig`：加上 `CONFIG_WIRELESS`、`CONFIG_CFG80211`、`CONFIG_CFG80211_WEXT`、`CONFIG_WLAN`。
- **Buildroot** `luckfox_pico_defconfig`：加上 `iw`、`libpcap`、`libsodium`、`usbutils`。
- **overlay**：`RK_POST_OVERLAY` 末尾追加 `overlay-rkfpv`（它在 OEM 打包之后执行，所以能覆盖 S21appinit）。

```bash
# 0. 主机依赖
sudo apt-get install -y device-tree-compiler gcc-multilib g++-multilib gperf texinfo \
                        flex bison gawk expect cmake lz4

# 1. SDK 完整编译一次（得到内核树和 buildroot staging）
```

## 9. 验证计划

**阶段 A：不接网卡，走 USB 网络**
- 原厂固件即可：`killall rkipc; rkfpv -s dst=<电脑IP>`，电脑上运行 `./play_video.sh h265`。
- 检查画面、颜色、码率；**横移时看有没有错位** → 用来区分是相机端问题还是链路问题。
- mavbridge：用 `luckfox-config` 打开 UART3，QGC 监听 UDP 14550。

**阶段 B：接网卡，完整链路**
- `lsusb` 能看到 8812，`iw dev` 显示 monitor 模式，地面站正常出图。
- 用 `rtp_jitter.py` 统计丢包；跑 MCS 2/3/4 × 不同码率的测试矩阵，和 majestic 对比错位情况。
- 发 SIGHUP 改码率，确认画面不中断。

## 10. 配置方式与远程修改

**本地配置**：编码参数在 `/etc/rkfpv.conf`，链路参数在 `/etc/wfb.yaml`（以后可以合成一个文件）。

**去掉 majestic 后失效的功能**：
- alink 自适应链路（依赖 majestic HTTP API）→ 要用的话，改成给 rkfpv 发 SIGHUP，或给 rkfpv 加一个 UDP 控制口。
- 地面站上依赖 majestic/`cli` 的远程设置菜单。

**空中远程改配置（SSH）**：
- MAVLink 通路不是 IP 网络，**SSH 走不了**，只能和飞控通信。
- 需要 `wfb_tun` 建 IP 隧道：机载 `10.5.0.10` ↔ 地面 `10.5.0.1`，无线端口 0x20/0xa0，和 OpenIPC 一致，地面站不用改。
- 待办：Buildroot 打开 `libevent`，加上 dropbear；`build-deps.sh` 编译 `wfb_tun`；`wfb.sh` 启动 tunnel。
- 改参数的流程：
  - 码率 / GOP：改 `rkfpv.conf`，然后 `killall -HUP rkfpv`，立刻生效
  - 分辨率 / 帧率：要重启 rkfpv
  - 无线参数：`wfb.sh stop && wfb.sh start`，链路会断 1–2 秒
- ⚠️ 改信道、link_id、密钥要小心：改错就连不回来了，只能落地后插 USB 或拔 TF 卡恢复。
- 备选方案：在 mavbridge 里拦截 PARAM_SET，用 QGC 参数页改 rkfpv 参数。工作量大，暂时不做。
